### Tier 2: Hygiene analyzer false-positive fix

**Bug:** `src/analyzers/hygiene.ts` `checkDebugStatements` / `checkTechDebtMarkers` / `checkMagicNumbers` did naive `line.match(regex)` with no string awareness, so any of these triggered false positives:
- `` const example = `console.log('x')`; `` → false positive debug-statement
- `const help = "// TODO before commit";` → false positive tech-debt-marker
- `const label = "Error 30000";` → false positive magic-number

Documented in `docs/ENHANCEMENTS.md` as "Smarter Hygiene Detection." First-impression-critical for downloaders — `maestro quality` runs by default on every `maestro report`, and template-heavy or fixture-heavy codebases were seeing wall-of-FP warnings.

**Fix:** New export `maskStringsOnly(line, state)` in `src/utils/string-scanner.ts` that blanks the interior of string literals (single quotes, double quotes, template literals — including multi-line via persisted state) while preserving column positions, quote characters, and comments. `analyzeHygiene` now creates a per-file scanner state and runs each check function against the masked line instead of the raw line.

**Why not also mask comments?** `checkTechDebtMarkers` REQUIRES `//`, `#`, or `/*` prefix — we want TODO/FIXME inside real comments to keep triggering. Masking comments would break legitimate detection.

**Known non-goal (not fixed this session):** Block-comment contents (`/* ... */`) are not masked. A regex that hits inside a block comment can still false-positive. Not a common pattern in practice; not documented before this session either. Filed mental note; not blocking.

**Tests added:** 8 unit tests on `maskStringsOnly` in `tests/string-scanner.test.ts`; 6 integration tests on `analyzeHygiene` in `tests/hygiene.test.ts` (including a mixed-line real-vs-string test and a multi-line template literal test). Removed the hygiene item from `docs/ENHANCEMENTS.md`.

**Verification:** Smoke test from plan verified — synthetic file with all three FP triggers produces zero hygiene findings. Self-audit went from 98/100 → 99/100 (hygiene reduced from 9 findings to 5).

### Tier 3: `maestro doctor` command

New meta-health check for maestro's own environment. Goal: prevent new-user bounces on Node version / install perms / npm reachability issues by giving them a clear diagnostic + actionable fix instead of a cryptic install error.

**Checks (7):**
- Environment: Node.js ≥ 20.12.0 (from engines), npm reachable, git reachable
- Connectivity: registry.npmjs.org reachable (HTTP GET, 5s timeout)
- Filesystem: write access to cwd, maestro on PATH
- Installation: maestro-dev version (read from bundled package.json)

**Output:** grouped PASS/FAIL/WARN with actionable Fix hints (`nvm install 22 && nvm use 22`, `npm install -g maestro-dev`, etc.). Non-zero exit if any FAIL.

**Files:**
- New: `src/commands/doctor.ts` — 8 exported check functions + orchestrator + renderer
- New: `tests/doctor.test.ts` — 18 tests covering each check + version comparison edge cases + full pipeline
- Modified: `bin/maestro.ts` — register doctorCommand + add to help text under Setup
